# 데이터 사전 (data/clean)

만든 날: 2026-11-07 · 만든 스크립트: `src/build_clean.py` · 원본 내려받은 날: 2026-11-05

이 문서는 정리본의 **모든 열의 뜻·단위·기준**을 정한다. 그래프, PPT, 학습, AI 보고서 모두 이 정의를 따른다. 여기 없는 해석(예: "거래량 = 전체 발전량")은 쓰지 않는다.

## 1. 지켜야 할 규칙

1. **원본(data/raw)은 읽기 전용.** 고치지 않는다. 원본 파일 이름도 그대로 둔다.
2. **정리본(data/clean)은 손으로 고치지 않는다.** 바꿀 게 있으면 `build_clean.py`를 고치고 다시 돌린다. 엑셀로 열어 저장하면 지문이 바뀌어 `manifest.py verify`에서 걸린다.
3. **값은 바꾸지 않는다.** 형식(긴 표로 펴기, 열 이름, 날짜 형식, 천 단위 쉼표 제거)만 바꾼다.
4. **빈칸은 빈칸(NA)으로 둔다.** 0으로 채우지 않는다. 0으로 볼지는 특징(feature) 단계에서 정하고, 그 결정을 그 단계 문서에 적는다.
5. **고치지 말고 표시한다.** 오타·누락은 `*_raw`에 원문을 남기고, 표준화한 값과 메모 열을 따로 둔다.
6. **모든 행에 출처가 있다.** `source_id` → `sources.csv`에서 원본 파일 이름 확인.
7. **쓰기 전에 검사한다.** `python src/manifest.py verify`가 "문제 0개"여야 한다.

## 2. 시간 기준 (가장 헷갈리는 부분)

| 데이터 | 원본 표기 | 정리본 열 | 뜻 |
| --- | --- | --- | --- |
| 전력수요 | `1시` ~ `24시` | `hour` 1–24, `hour_label` | 전력거래소 시간대 번호. `24`는 그날 마지막 시간대(다음 날 0시가 아님) |
| 태양광·풍력, 연료원 | 거래시간 `1`~`24` | `hour` 1–24 | 위와 같은 번호 체계 |
| 출력제어 | `1시`~`24시` 칸 | `h01_raw`~`h24_raw` | 위와 같은 번호 체계 |
| 기상 관측(ASOS) | `2023-01-01 00:00` | `datetime_kst` | 한국 시간, 0–23시 |
| 기상 예보 | UTC | `issue_date_utc`, `issue_hhmm_utc` | **9시간 더해 한국 시간으로 바꾼 뒤** 사용 |

- 전력 데이터의 시간대 `h`와 기상 시각을 맞출 때 기준은 `h시 = 관측 h:00`으로 한다. (예: 전력 13시 ↔ 기상 13:00) 이 대응은 **가정**이다. 1시간 어긋나도 일 단위 예측 결과는 거의 같지만, 시간별 그래프에는 이 가정을 각주로 단다.
- 날짜는 모두 `YYYY-MM-DD` 문자열, 한국 날짜.

## 3. 파일별 열

### demand_hourly.csv — 시간별 전국 전력수요 (2023-01-01 ~ 2025-12-31, 26,304행)

| 열 | 뜻 | 단위 |
| --- | --- | --- |
| date, hour, hour_label | 날짜, 시간대 번호, 원본 표기("13시") | |
| demand | 전국 전력수요 | **MW** (원본 머리말에 단위가 없음. 전력거래소 수요 자료의 통상 단위로 표기) |
| source_id | 출처 | |

- 원본 문자열 열(demand_raw)은 숫자 변환이 한 칸도 손실 없음을 검사한 뒤 뺐다.

### renewable_hourly.csv — 지역별 시간별 태양광·풍력 (620,016행)

| 열 | 뜻 | 단위 |
| --- | --- | --- |
| region_raw | 원본 지역 이름 ("전라남도", "광주시", "육지") | |
| region_std | 짧은 표준 이름 ("전남", "광주", "육지(합계)") | |
| region_level | `시도` 또는 `권역합계` | |
| fuel | 태양광 / 풍력 | |
| value_mwh | **전력시장 거래량** | MWh |
| value_blank | 원본 칸이 비어 있었는지 | True/False |

주의:
- **이중 집계 금지.** `권역합계`(육지, 제주) 행은 시도 행을 더한 값이다. 전국 합계는 `region_level == "시도"`만 더한다. 육지/제주 합계 행이 있는 기간이 일부라서 섞어 더하면 기간마다 값이 튄다.
- **거래량 ≠ 전체 발전량.** 전력시장에서 거래된 양만이다. 한전과 직접 계약(PPA)하거나 자가소비하는 태양광(지붕형 등)은 빠져 있다. 발표에서 "태양광 발전량"이라고 쓰면 "시장 거래 태양광"이라고 단서를 단다.
- 빈칸 30,581칸: 태양광은 거의 모두 밤(19시~다음 날 8시), 풍력은 2023년 초(S04)와 9~11월(S07) 파일의 일부 지역. 빈칸을 0으로 볼지는 특징 단계에서 정한다.
- 원본의 1,000 이상 값은 "1,028.44"처럼 천 단위 쉼표가 있다. 쉼표를 빼고 숫자로 바꿨고, 바뀌지 않은 칸이 0개임을 검사했다.

### fuel_hourly.csv — 연료원별 시간대별 설비용량·거래량 (514,680행)

| 열 | 뜻 | 단위 |
| --- | --- | --- |

- 연료원 이름이 해마다 다르다(2025년에 `전기저장장치(비중앙)`, `LPG` 등 추가). 합칠 때는 이름을 바꾸지 말고 매핑표를 따로 만든다.

### kma_forecast_{2023,2024,2025}.csv.gz — 기상청 단기예보 과거 발표분 (`src/build_forecast.py`)

5개 지역 × 3개 요소 × 3년 = 45개 조합. 원본은 `data/raw/kma_forecast/zips/` (137개 CSV, 서버 2분 제한 때문에 2023·2024년은 석 달/한 달 단위로 나눠 받음).

| 열 | 뜻 | 단위 |
| --- | --- | --- |
| station_area | 대표 지역 (광주·목포·전주·대구·부산) — ASOS 지점과 같은 도시 | |
| dong, grid | 예보 지점 (운암1동 59_75, 연산동 50_67, 송천1동 63_90, 신암1동 89_91, 대청동 97_74) | 5km 격자 번호 |
| element | SKY 하늘상태(1 맑음·3 구름많음·4 흐림), POP 강수확률, TMX 일최고기온 | 코드 / % / °C |
| issue_date_utc, issue_hhmm_utc | 발표 날짜·시각 (**UTC**, 원본 머리말 기준) | |
| lead_h | 원본의 `forecast` 값 (+6 → 6) | 시간 |
| value | 예보값 | |

주의:
- **발표 시각은 UTC다.** 한국 시간 = UTC + 9시간 (2025 원본에는 기상청이 계산한 KST 열이 함께 있어 확인됨). 전날 17시(KST) 발표분 = 같은 날 08:00 UTC.
- **TMX의 lead_h 의미는 아직 검증 전.** 시간마다 값이 바뀌는 형태라 SKY·POP와 같은 "몇 시간 뒤" 뜻인지 ASOS 실제 최고기온과 맞춰 확인한 뒤 특징으로 쓴다.
- **2023·2024년 원본 결함:** 일(day) 칸이 깨진 블록(값 모두 0)과 다른 날 자료가 섞인 블록을 뺐다 (보충분 포함 각각 141,352행, 8,981행). 고치거나 채우지 않았다. 뺀 내역은 `kma_forecast_excluded.csv`.
- 결함으로 빠진 날(363 조합·일)은 **하루 단위로 다시 요청해 보충**했다 (`refill_001~066.zip`, 2026-11-07). 하루 단위로 받으면 결함 없이 오는 경우가 대부분이었다.
- **결측 표시값 -999.9** (원본에는 -999.900024)는 숫자가 아니라 빈칸으로 바꾸고 `value_missing_code=True`로 표시했다. 2023-11-07 발표분 하늘상태가 5개 지역 모두 이 값이다 (2,540행). 영하의 최고기온(-1 ~ -8°C)은 실제 값이라 그대로 둔다.
- 그래도 빈 **20 조합·일은 원본 손상으로 보고 빈칸**으로 둔다 (2023년 13, 2024년 7, 2025년 0; 조합별 최대 3일, `kma_forecast_coverage.csv`). 특징에서는 결측(NA)으로 둔다.
- 중복된 (발표·선행시간)은 값이 같을 때만 하나로 합쳤다 (충돌 0건).

## 4. 정보가 언제 알려지는지 (누설 방지)

전날(D-1) 17시에 "내일 출력제어가 있을까"를 예측한다고 가정한다. 이때 쓸 수 있는 것만 입력으로 쓴다.

| 정보 | D-1 17시에 알 수 있나 | 예측 입력으로 |
| --- | --- | --- |
| 내일 날짜·요일·공휴일 | 예 | 사용 |
| 기상청 단기예보 (D-1 17시 발표분) | 예 | 사용 |
| 오늘까지의 출력제어 실적 (최근 30·90일 횟수) | 예 | 사용 |
| 오늘까지의 수요·태양광 실적 | 예 | 사용 (어제·오늘 값) |
| 내일 실제 기상 관측 | **아니오** | 사용 금지 (분석·설명용으로만) |
| 내일 실제 수요·태양광 | **아니오** | 사용 금지 (분석·설명용으로만) |

특징 표(features)의 열마다 `D-1` / `D0` 표시를 붙이고, 모델에는 `D-1` 열만 넣는다. D0 열로 만든 결과는 "상한선(참고용)"이라고 따로 표시한다.

## 5. 알려진 한계

- 전력망 제약(송전선 혼잡), 원전 정비 일정, 양수·ESS 운전 계획은 공개 자료가 없다. 게시판 제어사유에 "전력망"이 많아 이 부분이 성능의 상한을 정한다.
- 2026년 태양광·연료원(원전) 자료는 아직 공개 전(2027년 공개 예상). 2026년 수요는 EPSIS 실시간 전력수급으로 채웠다 (`data/clean/epsis_hourly.csv`: date, hour(1~24, 시간 끝 기준), supply_mw 공급능력, load_mw 수요, reserve_mw 예비력, n_points 평균에 쓴 5분 값 개수. 만드는 코드 `src/build_extra.py`, 2026-11-11 추가). 2026년 기상 예보는 아직 받지 않았다.
- 게시판 날짜별 정리본 `data/clean/kpx_board_daily.csv` (육지만): date, notice_forecast 전날 전망 공지 여부, occurred 실제 출력제어 여부, start_h·end_h 시작·종료 시각, reason_grid·reason_supply 제어 사유(전력망·수급). 공식 실적과 겹치는 149일 모두 일치.
- 공휴일 목록은 손으로 입력했다: `data/manual/holidays_kr.csv` (2023~2026, 81일). 열: date, name, kind(법정·대체·임시·선거·근로자의날), official_holiday(관공서 휴일 Y/N), note, source. 근로자의 날(2023~2025)은 관공서 휴일이 아니라 N으로 따로 표시. 2026-05-01은 "노동절"로 이름이 바뀌고 관공서 공휴일이 되어 Y (2026-04-28 국무회의 의결, 2026-11-11 고침). 2025-10-10은 임시공휴일 아님(정부 미지정), 2026-07-17 제헌절은 공휴일 복원. 2026-11-11 언론 보도·정부 발표와 대조: 고친 것은 2026-05-01 하나. 2026-09-28(추석 다음 월요일)은 임시공휴일로 지정되지 않음을 확인. 한국천문연구원 특일정보와의 최종 대조는 팀원이 한 번 더 한다.
- 전력거래소가 나중에 수정정산으로 값을 바꿀 수 있다. 다시 내려받으면 지문이 달라지므로, 새 파일은 새 이름으로 넣고 CHANGELOG에 적는다.
