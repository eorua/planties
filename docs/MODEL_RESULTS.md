# 모델 결과 (2차, 2026-11-10)

만드는 코드: `src/build_features.py` → `src/train.py` · 결과 파일: `outputs/` (metrics.json, test_predictions.csv, learning_curve.csv, feature_importance.csv, 그래프 4개)

## 1. 어떻게 평가했나

- **실제 운영처럼:** 매달 1일에 그 전날까지의 모든 자료로 다시 학습하고, 그달 하루하루를 전날 17시 기준으로 예측한다.
- **검증 (2025년 1~6월, 출력제어 55일):** 모델 설정을 여기서만 정했다. 개선안은 2024년 3월까지 넓힌 검증(82일)으로도 확인했다.
- **경보 기준:** 매달 1일에 직전 12개월의 예측 결과로 다시 정한다 (그달의 답은 보지 않는다). 2차에서 바꾼 부분, 7장 참고.
- **시험 (2025년 7~12월, 출력제어 27일):** 정해진 설정 그대로 한 번만 평가했다. 대회 규정의 "검증 사례 10건 이상"을 넉넉히 채운다.
- **비교한 모델:** ① 간단한 규칙(봄·가을 + 쉬는 날 + 맑음 예보 + 최근 출력제어, 학습 없음) ② 로지스틱 회귀 ③ 그래디언트 부스팅(사이킷런 HistGradientBoosting)
- **지표:** 출력제어가 없는 날이 85% 이상이라 정확도는 쓰지 않는다. 무작위로 찍으면 0.15가 나오는 PR-AUC(위험한 날을 위로 올리는 능력)와 재현율(실제 출력제어 중 잡은 비율), 정밀도(경보 중 맞은 비율)를 본다.
- 학습 시간: 전체 과정(설정 탐색 + 매달 재학습 + 학습 곡선)이 약 1분 30초.

1차(경보 기준을 검증 기간에 한 번 고정)에서는 그래디언트 부스팅이 26일을 잡는 대신 헛경보가 55번이었다. 기준을 매달 다시 정하게 바꾼 뒤 헛경보가 18번으로 줄었다 (7장).

### 읽는 법
- **그래디언트 부스팅이 가장 좋다.** 같은 수(24일)를 잡으면서 헛경보가 규칙보다 적다(18번 대 22번). 심사에서 "규칙으로도 되지 않냐"는 질문의 답이다.
- **간단한 규칙도 꽤 강하다.** 이 문제의 큰 줄기가 "봄·가을 + 쉬는 날 + 최근 흐름"이라는 뜻이다.
- **놓친 3일**(9/20, 9/23, 10/7 추석)은 모두 예보가 흐리거나 비였는데 출력제어가 났다. 게시판 사유는 대부분 "전력망 제약"이라, 공개 자료로는 미리 알기 어려운 경우로 본다.
- 시험 기간 출력제어가 27일뿐이라 결과가 몇 %p씩 흔들린다. 모델 사이의 차이를 과장하지 않는다.

## 3. 무엇이 중요했나

그래디언트 부스팅에서 각 입력을 섞어 버렸을 때 성능이 얼마나 떨어지나 (시험 기간):

1. **쉬는 날** (주말·공휴일) — 압도적
2. **마지막 출력제어 후 지난 날** — 최근에 있었으면 또 있을 가능성이 높다
3. 지난주 최저 수요
4. 계절
5. 예보 최고기온 — 너무 덥거나 추우면 냉난방 수요가 늘어 출력제어가 줄어든다
6. 지난주 같은 요일 한낮 수요

로지스틱 회귀 계수로 보면 **태양광 설비용량**(해마다 늘어나는 추세), 쉬는 날, 최근 7일 출력제어, **예보 맑음 비율**이 위험을 올리고, 예보 최고기온·어제 한낮 수요가 위험을 낮춘다. 전력계통 상식(낮은 수요 + 많은 태양광 = 남는 전기)과 맞는다.

매달 재학습할 때 "최근 N개월만" 쓰도록 바꿔서 같은 시험 기간을 다시 평가했다.

- 2023년(출력제어가 거의 없던 해)을 넣으면 시험 성능이 오히려 내려갔지만, **검증 기간에서는 전체(0.66)가 18개월(0.61)·24개월(0.61)보다 나았다.** 시험 결과만 보고 기간을 바꾸면 결과를 부풀리는 셈이라, 미리 정한 "전체"를 유지했다.
- 결론: **더 옛날 자료를 모아도 나아질 근거는 없다.** 2023년 이전에는 출력제어가 거의 없었고, 계통 상황도 달랐다. 남은 한계는 자료의 양보다 **비공개 정보(송전망 제약, 원전 정비, 양수·ESS 운전)** 쪽이다.

### 왜 이 문제에 "표 자료용 머신러닝"인가
- 자료가 **날짜마다 1행 × 35개 항목**인 표다. 이런 자료에서는 트리 부스팅 계열(LightGBM, XGBoost, 사이킷런 HistGradientBoosting)이 가장 많이 검증된 강자다.
- **사례가 적다** (출력제어 2023~2025년 111일). 파라미터가 많은 딥러닝은 외워 버리기 쉽다.
- **빈칸이 있다** (2024년 원전, 예보 20 조합·일). 그래디언트 부스팅은 빈칸을 그대로 처리한다.
- **설명이 필요하다.** 어떤 입력이 위험을 올렸는지 보여 줘야 한다 (대회 주제가 "원인과 대응 설명").

### 결론
- **그래디언트 부스팅을 본 모델로 유지한다.** 넓힌 검증에서 단일 모델 1위, 가장 어려운 2024년에서도 1위, 시험에서 같은 재현율일 때 경보가 가장 정확했다(정밀도 70%). 빈칸을 그대로 처리하고 원인 설명도 가능하다.
- **로지스틱 회귀는 설명용으로 함께 쓴다.** 성능은 낮지만 "어떤 입력이 위험을 얼마나 올리나"가 계수로 바로 보인다.
- **앙상블(SVM+부스팅)은 넓힌 검증에서 0.54로 근소하게 앞서지만**, 차이(0.01)가 잡음보다 작고 설명이 어려워져 채택하지 않는다. 발표에서는 "여러 모델을 섞어도 크게 나아지지 않았다"로 쓴다.
- 신경망(MLP)·랜덤 포레스트·k-최근접 이웃은 검증·시험 모두 부스팅보다 낮다. 나이브 베이즈는 입력끼리 서로 독립이라는 가정이 깨져(예: 수요와 계절, 쉬는 날과 요일) 쓸 수 없다.

### 시험해 보지 못한 것
- **LightGBM, XGBoost, CatBoost:** 그래디언트 부스팅과 같은 계열이다. 지금 환경은 패키지 설치가 막혀 있어 돌리지 못했다. 1천 행 규모에서는 보통 사이킷런 버전과 성능 차이가 작다.
- **설명형 부스팅(EBM, interpret 패키지):** 부스팅만큼 정확하면서 입력별 효과를 그래프로 보여 주는 모델이라 발표용 설명에 유리하다. 설치되면 1순위로 시험해 볼 후보.
- **시계열 딥러닝(LSTM, 시계열 기반 대형 모델):** 연속 값을 예측하는 데 맞춰져 있고, 드문 사건 분류에는 사례가 너무 적다.

### 모델을 바꾸는 것보다 효과가 클 것
1. **경보 기준을 계절에 맞추기** — 지금 가장 큰 약점(하반기 헛경보)이 모델 종류가 아니라 기준값에서 나온다.
2. **확률 보정** — 숫자를 "출력제어 확률 70%"처럼 그대로 읽을 수 있게.
3. **입력 보강** — 태양광이 많은 충남 예보, 시간대별(한낮 몇 시간) 예측.

### 시험해 본 것과 넣은 이유

| 개선안 | 넣은 이유 (전력계통 관점) |
| --- | --- |
| ① 더위·추위 정도 (`fc_cool_deg` = 최고기온 28°C 넘는 만큼, `fc_heat_deg` = 10°C 밑도는 만큼) | 냉난방 수요가 늘면 남는 전기가 줄어 출력제어가 줄어든다. 1차에서 7월 무더운 주말에 헛경보가 몰렸다. |

| ③ 예보 변화 (`fc_clear_delta`, `fc_pop_delta`) | 이틀 전 예보와 전날 예보가 다르면 그만큼 불확실하다. 놓친 날이 대부분 "예보는 흐림"이었다. |
| ④ 방향 제약 (단조 제약) | "쉬는 날·맑음·태양광 설비 → 위험 증가, 수요·강수확률·더위 → 위험 감소"를 모델에 강제한다. 한두 번의 예외(예: 무더운 주말 출력제어)를 일반 규칙으로 잘못 배우지 않게. |
| ⑤ 경보 기준 정하는 방식 | 1차의 기준(봄에 정한 한 값)이 하반기에 너무 낮았다. 매달 과거 예측 결과로 다시 정한다. |

| C 새 항목 ①②③ 추가 | 0.49 | 0.23 | 0.60 | 0.85 |
| D 새 항목 + 방향 제약 | 0.49 | 0.17 | 0.64 | 0.75 |

→ **검증에서 좋아지지 않아 본 모델은 A(기존 항목)를 유지한다.** 새 항목은 특징 표에 남겨 두되 본 모델에는 넣지 않는다 (`train.py`의 `NOT_USED`).

**검증과 시험이 엇갈렸다.** 새 항목(C)은 시험에서 0.85로 크게 좋았지만, 시험 결과를 보고 고르면 성능을 부풀리는 셈이라 채택하지 않았다. 엇갈린 이유로 짐작되는 것: 새 항목이 노리는 상황(한여름 무더위 속 주말)이 검증 기간에는 거의 없고 시험 기간(7월)에만 있었다. 이 짐작은 **2026년 자료로 독립 시험**을 해야 확인할 수 있다 (5장 1번).

### 경보 기준 정하는 방식 (공정 비교: 모든 방식이 그달 1일 이전 정보만 사용)

| 방식 (모델 A) | 검증 F1 (2025년 1~6월) | 시험: 잡음 / 헛경보 / 놓침 (기록만) |
| --- | --- | --- |
| 1차 방식: 검증 기간 안에서 정한 한 값 | (검증 기간 안에서 정해 공정 비교 불가) | 26 / 55 / 1 |
| 고정: 2024년 3~12월 예측으로 한 번 | 0.66 | 24 / 28 / 3 |
| **최근 12개월: 매달 다시** | **0.66** | **24 / 18 / 3** |
| 누적: 매달 지금까지 전부로 | 0.66 | 24 / 31 / 3 |

→ 세 방식이 검증에서 같았다. **계절과 해마다 바뀌는 상황에 맞춰 가는 운영 원칙**에 따라 "최근 12개월, 매달"을 채택했다. 시험에서도 가장 좋았지만 그건 고른 근거가 아니다. 어느 공정한 방식을 써도 1차보다 헛경보가 크게 줄었다(55번 → 18~31번).

### 고려했지만 하지 않은 것
- **확률 보정**: 순위는 그대로라 경보 성능은 같다. 발표용 표시(위험도 3단계)로 대신한다.
- **전력거래소 전날 전망 공지를 입력으로**: 운영자가 낸 "정답에 가까운 예측"을 넣는 셈이고, 2025년 하반기에는 공지가 거의 없어 쓸 수 없다. 비교 대상으로만 쓴다.
- **시간대별 예측**(몇 시에 제어되나): 사례 수는 늘지 않고 구조가 복잡해진다. 시연에서 필요하면 게시판의 제어 시각으로 보여 준다.
