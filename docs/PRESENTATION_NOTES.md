## 2. 핵심 숫자 (2026-11-12, 두 숫자 체계)

**발표의 본 숫자는 "공개 자료 모델"이다.** 전력거래소 출력제어 실적이 며칠~몇 주 늦게 공개되어, 출력제어 이력을 전날 17시에 공개 자료로 알 수 없기 때문이다 (MODEL_RESULTS 11장). 지금까지의 모델은 "실시간 출력제어 정보가 있는 운영자라면"으로 함께 보여 준다.

| 숫자 | 공개 자료 모델 (본 숫자) | 실시간 정보 모델 (함께 제시) | 출처 |
| --- | --- | --- | --- |
| PR-AUC (무작위 0.15) | **0.59** (0.42~0.81) | 0.78 (0.60~0.93) | outputs/public/metrics.json, outputs/metrics.json |
| 전날 경보로 잡은 출력제어 (27일 중) | **23일** (놓침 4) | 25일 (놓침 2) | 같은 파일 |
| 위험도 "낮음"인 날 출력제어 | **44일 중 0일** | 68일 중 0일 | outputs/public/explain_summary.json |
| 같은 재현율(80%)에서 경보 정확도 | 50% (규칙 45%) | 82% (규칙 52%) | test_predictions.csv |
| 헛경보 | 36번 | 31번 | metrics.json |
| 규칙 PR-AUC | 0.49 | 0.52 | metrics.json |

말하는 방법 (예): "공개 자료만으로 출력제어 27일 중 23일을 전날 알렸고, '낮음'이라고 한 44일에는 한 번도 출력제어가 없었습니다. 출력제어 실적이 실시간으로 공개된다면 PR-AUC가 0.59에서 0.78로 올라갑니다."

**주의:** 공개 자료만으로는 모델이 간단한 규칙을 확실히 이기지 못한다(검증 0.61 대 0.62). "AI가 규칙보다 훨씬 낫다"고 말하지 않는다. 모델의 장점은 점수·위험도·원인 설명, 기온·수요 반영, 그리고 이력 정보가 생기면 바로 0.78로 올라가는 구조다.

## 2-2. 2026년 독립 시험 (2026-11-12, MODEL_RESULTS 12장)

- 결과를 보기 전에 계획을 저장소에 올리고(11-11), 2026년 1~10월(출력제어 70일)로 시험했다. 태양광·원전 입력은 2026년 미공개라 뺐다.
- 말할 숫자: **봄(3~5월) 출력제어 48일 중 44~46일을 전날 경보**, **전력거래소 공지 없이 생긴 42일 중 33~38일 경보**, 위험도 하위 40% 날(약 120일)에 출력제어 3~4일.
- PR-AUC: 실시간 정보 0.64 (규칙 0.54), 공개 자료 0.50 (규칙 0.49), 무작위 0.23.
- 솔직히 말할 것: 여름·가을은 약하다(10월 출력제어 1일에 경보 15~25일). 단 10월 실적 글은 11-12 현재 게시판에 아직 안 올라와(9월분도 10-22에 몰아서 올라옴) 10월 정답은 잠정이다. 공개 자료만으로는 간단한 규칙과 비슷하다. 미리 넣은 새 항목은 효과가 없었다.
- 예상 질문 "2026년엔 왜 떨어졌나?" → 태양광·원전 입력이 아직 공개되지 않아 빼고 돌렸고, 2026년 가을은 2025년과 달리 출력제어가 거의 없었다. 그래도 계획대로 그대로 보고했다.

## 4. 원전 입력 (B안으로 확정, 2026-11-11 저녁)

| 선택지 | 시험 PR-AUC | 잡음 / 헛경보 / 놓침 | 검증 PR-AUC | 비고 |
| --- | --- | --- | --- | --- |
| A 어제 하루 전체 평균 (이전) | 0.782 | 24 / 15 / 3 | 0.650 | 17시 이후 7시간이 섞임 (규칙 위반) |
| **B 어제 1~16시 평균 (채택)** | **0.776** | **25 / 31 / 2** | 0.648 | 규칙 지킴 |
| C 원전 빼기 | 0.723 | 25 / 31 / 2 | 0.614 | 2026 시험 모델과 같은 조건 |

- 고른 이유: 성능이 아니라 "전날 17시에 알 수 있는 정보만" 규칙. 원전은 하루 출력이 거의 일정해 값 차이가 작다(중앙값 0.003GW).
- 원전 입력의 근거(전력계통 관점): 원전은 출력을 거의 줄이지 못하는 기저 발전이다. 원전이 많이 돌면 한낮에 남는 전기를 받아 줄 여유가 줄고, 정비로 빠지면 여유가 생긴다. 정비 일정은 공개되지 않아서 "어제 원전 출력"을 정비 상태의 대용치로 쓴다.
- 주의: 2024년은 원전 자료가 통째로 없어 빈칸이다. 그래디언트 부스팅은 빈칸을 "2024년이라는 표시"처럼 쓸 수 있다. 원전 효과를 발표에서 크게 말하지 않는다.

## 5. 우리만 아는 배경 (발표·질의응답에서 쓸 이야기)

**왜 전날 17시인가**
- 실제로 쓸 수 있는 예보가 되려면 전날 알 수 있는 정보만 써야 한다. 기상청 단기예보 17시 발표분(국제표준시 08시)을 쓴다.
- 출력제어는 늦어도 16~17시에 끝난다 (2023년 이후 170일 중 69일이 17시까지 이어짐, 18시 이후는 없음).

**시험을 공정하게 한 방법**
- 시간 순서대로 나눔: 검증 2025년 1~6월(설정은 여기서만), 시험 2025년 7~12월(한 번만 평가).
- 매달 1일에 그 전날까지 자료로 다시 학습 (실제 운영과 같은 방식).
- 2026년 독립 시험은 결과를 보기 전에 계획을 저장소에 먼저 올렸다 (docs/TEST_2026_PLAN.md, 2026-11-11).
- 누설 점검: 정답이 입력으로 새는 경로가 없는지 9가지를 확인 (docs/LEAKAGE_AUDIT.md). 일부러 당일 실제값을 넣으면 0.80이 되는데, 우리 모델이 0.78(점검 당시)이라 "답을 미리 본 것 아니냐"는 질문에 이 표로 답한다.

**데이터 품질 작업 (실현 가능성 점수용)**
- 공개 자료 8종을 원본 그대로 보관하고 파일 지문(SHA-256)을 기록, 자동 검증 500여 개.
- 태양광 원본의 "1,028.44" 같은 천 단위 쉼표 값 461칸이 숫자로 안 읽히던 문제를 찾아 고침.
- 기상청 예보 원본의 깨진 날짜 블록 363 조합·일을 하루 단위로 다시 받아 15로 줄임 (최종 20 조합·일만 빔).
- 시간 기준이 자료마다 다름: 전력 1~24시, 관측 0~23시, 예보는 국제표준시. 모두 맞춰 씀.
- 2026년 수요는 공공데이터 파일이 아직 없어 EPSIS 실시간 수급으로 대신 (오차 중앙값 0.11%).
- 공휴일 목록을 정부 발표와 대조: 2026-05-01 노동절이 관공서 공휴일이 된 것 반영.

**놓친 날 (공개 자료 모델: 9/20, 9/23, 10/7 추석, 10/20 / 실시간 정보 모델: 9/20, 9/23)**
- 9/20·9/23은 두 모델 모두 놓쳤다. 예보가 흐리거나 비였는데 출력제어가 났고, 게시판 사유는 대부분 "전력망 제약". 공개 자료로는 미리 알기 어려운 경우로 설명한다.

**무엇이 중요했나 (그래디언트 부스팅, 섞었을 때 떨어지는 정도)**
- 1위 쉬는 날(압도적), 2위 마지막 출력제어 후 지난 날, 그다음 예보 최고기온·계절·지난주 최저 수요·어제 한낮 수요.
- 전력계통 상식과 맞는다: 낮은 수요 + 많은 태양광 = 남는 전기. 더우면(냉방) 출력제어가 줄어든다.

**시연 방식**
- 2026년 태양광 실적이 2027년에 공개되어 실시간 예측은 불가 → 2025년 날짜를 골라 "그 전날 17시였다면"으로 재현.
- 구상 화면 예시 날짜: 2025-11-02(일), 확률 99.7%, 실제 출력제어 있음.

## 6. 한계 (먼저 밝힐 것)

- 송전망 제약, 원전 정비 일정, 양수·ESS 운전 계획은 공개 자료가 없다. 이 부분이 성능의 상한.
- 시험 출력제어가 27일뿐이라 결과가 ±0.15 흔들린다 → 2026년 독립 시험(70일)으로 보완.
- 헛경보 수는 경보 기준 하나에 크게 흔들린다 (15~31번, 지금 31번).
- 태양광 입력은 정산값으로 학습했다. 실제 운영에서는 당일 실시간 추정치만 있다.
- 출력제어 실적이 늦게 공개되어 공개 자료 모델은 출력제어 이력을 쓰지 못한다(0.59). 실시간 공개되면 0.78까지 오른다 → 정책 제안으로 연결.

| 전력거래소도 전날 공지를 하지 않나? | 같은 수만큼 경보하면 공지가 더 정확하다(84% 대 65%). 운영자는 송전망 정보를 갖고 있기 때문. 대신 공지가 없던 출력제어 27일 중 12일을 모델이 잡았고, 2025년 7~11월처럼 공지가 거의 없던 기간에도 매일 위험도와 이유를 준다 |
| 누가 쓰나? | 태양광 발전사업자(정비·ESS 충전 계획), 계통 운영 참고 |
| 원인 설명은 믿을 수 있나? | 입력 묶음을 하나씩 평균값으로 바꿔 점수가 얼마나 내려가는지 잰 것. 모델이 무엇을 봤는지를 보여 줄 뿐 실제 원인의 증명은 아니다 |
| 헛경보가 31번이나 되는데? | 경보 기준 하나에 15~31번으로 흔들린다(7월에 17번 몰림). 순위 능력(PR-AUC)은 안정적이고, 시연에서는 확률과 위험도 3단계로 보여 주고 최종 판단은 사람이 한다 |
